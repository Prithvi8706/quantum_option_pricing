Date: 4 October 2026. Scope: discover and read four existing same-target replacement records. No project modules were imported, no gates or scientific tests were replayed, and no backend or timing experiment was run. All original sources and receipts were read-only. This review adds no implementation credit and does not complete C12.

The corpus follows `docs/limitation_audit_20261001/CONTRACT_AND_EVIDENCE.md`, C12, and the exact replacement records linked by `docs/limitation_audit_20261001/EXECUTION_RESULTS.md` and `CONSTANT_MULTIPLIER_RESULT.md`. ## 1. Exact shared-prefix coefficient lookup

Numerical target: `out[j] ^= table[address mod 2**bits][j]`, coefficients reduced modulo each unchanged output width, omitted table rows treated as zero, arbitrary initial outputs allowed, address preserved and prefix scratch cleaned. The real log table is still 32 rows by nine 72-bit outputs, with 40 fractional bits. Financial IR nodes, tables and inputs are preserved.

Structural change: `research/controlled_source_completion/exact_lookup.py` factors the first table row into an unconditional XOR and recursively shares address prefixes. `research/controlled_source_completion/primitives.py:93` retains the historical repeated equality scan, and its dispatch keeps both lowerings selectable. This is a meaningful change of lookup algorithm, without coefficient approximation, measurement or relative-phase gates.

Correctness evidence: `research/limitation_audit_20261001/test_lookup.py` prescribes all-address XOR/cleanup/inverse checks, partial and constant tables, ignored high address bits, cache separation and a complete small IR graph. A small complex state entangled with a reference is checked using Qiskit `Statevector`; the same test also spells out the seven-T Toffoli expansion and checks phases. `results/limitation_audit_20261001/lookup_v2/summary.json` has four `leaves` rows (`log`, `atan`, `cos`, `cdf`) with `every_address_and_inverse_passed=true`. Its `cases[*].replays` contain expected outputs, actual values and `all_input_and_workspace_bits_restored=true`: three B4x12 inputs and one B8x52 input. This review did not rerun those tests or replay the source circuits.

Cost evidence: the summary's log row records `(qubits, t_count, t_depth)` changing `(724,3136,1600)` to `(724,420,226)`. The full-source lookup-only saving is small, about 0.11% of T gates. `lookup_v2/protocol.json` explicitly restricts the claim to arithmetic-source resources. `experiment_lookup.py` copies and hash-checks non-lookup leaf binaries, but this review does not independently verify every historical binary or the full receipt inventory.

Toolchain overlap: the replacement still emits through `Program`, uses `primitives.basis_run` and `primitives.resources`, and integrates through the same `compiler`, financial IR and `parallel_source`. The Qiskit complex-state check supplies a differently structured check for a small leaf, not a separate complete pricing backend.

## 2. Exact signed truncated carry-save multiplication

Numerical target: XOR `((signed_w(a) * signed_w(b)) >> f) mod 2**w` into an arbitrary full-width output, preserving inputs and cleaning scratch. Production interface is width 72 and fraction 40; signed floor/shift and modular output semantics remain unchanged.

Structural change: `research/controlled_completion_followup/truncated_multiplier.py` repeatedly adds partial products with carry propagation. `research/controlled_source_completion/carry_save_multiplier.py` instead reduces partial-product columns with reversible carry-save compressors, performs one final carry-propagating addition and applies the same exact sign corrections. Both generate only the low `w+f` product bits. The shared algebra is `signed(A)*signed(B) = A*B - sign(A)*B*2**w - sign(B)*A*2**w (mod 2**(w+f))`; the double-sign term vanishes for `0 <= f <= w`.

Correctness evidence: `research/limitation_audit_20261001/test_carry_save_multiplier.py` prescribes exhaustive signed pairs at widths 1 through 4, every supported fraction, and signed edges/random inputs at `(32,12)`, `(72,40)` and `(96,64)`, including arbitrary outputs and alternating inverse checks. It reuses the independent Python signed-integer expected-value oracle `check_case` in `research/controlled_completion_followup/test_truncated_multiplier.py`. This oracle differs from the compressor algorithm, but its gate execution still uses the same `basis_run`. `multiplier_v2/summary.json` records one `gate_replay` per B4x12/B8x52 case, with expected output equality, restored inputs/workspace and `passed=true`.

Cost evidence: `results/limitation_audit_20261001/multiplier_v2/leaves/9d1f0ace5d924241b3d0.json` records the candidate leaf: 14,148 qubits, 198,520 T gates and T-depth 3,696. The retained baseline leaf comparison in `EXECUTION_RESULTS.md` is 441 qubits, 289,968 T gates and T-depth 90,592. The summary records B4x12 capped depth 2,784,902 at 550,158 qubits and B8x52 depth 2,995,256 at 4,460,490 qubits. These include the prior exact lookup replacement; they are not standalone multiplier speedups. `uniform_limit_best_depth=6079060` for B4x12 retains the failed uniform-schedule result, which was worse than lookup-only depth 6,026,790. The memory-capped first-fit schedule is the accepted resource accounting.

Toolchain overlap: both multiplier builders reuse the same `Program`, `add`, `copy` and `subtract`; both use `primitives.resources` and the same gate interpreter. `experiment_multiplier.py` subclasses `LookupOnlyLibrary` and uses the same IR, compiler and scheduling stack. This is structural arithmetic diversity and an independent integer specification, with shared substrate and cost assumptions. All-to-all logical scheduling, exact seven-T CCX lowering and input/scratch conventions remain common.

## 3. Guarded exact ln(2) constant multiplication

Numerical target: unchanged positive integer coefficient `762123384786`, width 72, fraction 40 and clean full-width XOR output. At the selected SSA sites, the input is `A = U << 40`, so `signed72(A) = signed32(U)*2**40` and the desired shifted product equals `signed32(U)*762123384786` modulo the unchanged 72-bit output. This equivalence is conditional on the same graph proving the low 40 input bits zero; matching the coefficient alone is insufficient.

Structural change: `research/controlled_source_completion/constant_multiplier.py` constructs a signed-digit expansion and carry-save tree, using 13 nonadjacent signed terms rather than 23 positive binary terms. It also implements both binary/signed-digit shift-add alternatives. Its exact negative-bit identity is `-b*2**j = (1-b)*2**j - 2**j`. `has_zero_low_proof` requires a same-graph `bits` producer with an integer shift at most `-fraction`. Unguarded sites retain their previous general leaf. The local emitter does not dynamically validate a falsely asserted promise.

Correctness evidence: `research/limitation_audit_20261001/test_constant_multiplier.py` prescribes an independent signed-integer specification, small-word enumeration across four strategies, real coefficient signed extremes/random values, historical-leaf comparison, nonzero outputs, inverse execution, invalid parameter/promise controls, guarded dispatch and cache corruption checks. The false-promise control deliberately yields zero for input 2 although the generic target would yield one, demonstrating why the guard is required. `constant_multiplier_v1/B4x12/signed-digit-carry-save/input_proofs.json` and its B8x52 counterpart retain the actual SSA witnesses. `summary.json` records 78 proved B4x12 calls and 650 B8x52 calls, with three and one complete source replays respectively; the replays include 30 and 234 negative specialized operands respectively.

Cost evidence: `constant_multiplier_v1/leaves/8b42212b3a9fb0f6bb47.json` identifies the retained `signed-digit-carry-save` leaf and its explicit `input_contract.zero_low_bits=40`. The summary records leaf `(qubits,t_count,t_depth)` `(433,80808,46176)` to `(1405,11396,1152)`, then accepted capped depths 2,436,454 and 2,624,696 at the prior B4/B8 qubit caps. These are successive improvements on `multiplier_v2`, already containing lookup and variable multiplication. `fixed_batch_t_depth` is a counterfactual diagnostic: the fixed batches exceed the new scratch caps (569,531 and 4,623,695 qubits), despite coincidentally matching the valid repacked depths. Only `best.candidate` and the selected `schedule_capped.json` support the same-budget claim.

Toolchain overlap and provenance: the same `Program`, carry-save compressor idea, primitives, compiler, IR and first-fit scheduler remain in use. `constant_multiplier_v1/executed_experiment_constant_multiplier.py` is the archived producer; `protocol.producer_sha256` and `verification.executed_producer_sha256` agree at `2a0aeaa2d0d440ea0113869fdbe93a40b16bdb181f047859202a18841ca79c44`. The verification reports identical ASTs despite a different maintained-producer byte hash. That report is existing evidence, not a new AST check in this review. Its `tests.evidence` explicitly says the 61 passes were an observed historical terminal run; the finalizer checks artifacts rather than executing tests. The earlier 66-test receipt overlaps this suite and must not be added as independent evidence.

## 4. Dynamic cleanup of the same five-control MCX fragment

Numerical target: toggle one arbitrary target iff all five controls are one, preserve logical data including a reference, and return the three clean scratch bits to zero. The baseline is the actual `primitives.mcx` ladder, with seven CCX gates. Logical inversion repeats this verified MCX channel; it does not reverse the measurement instruction stream.

Structural change: `research/limitation_audit_20261001/experiment_mcx_cleanup.py` retains the three forward ANDs and target CCX, then replaces three inverse ANDs with H/measurement and outcome-conditioned CZ/X cleanup. It emits `results/limitation_audit_20261001/mcx_cleanup_v1/mcx5.qasm`. This is a dynamic backend fragment with an explicit integration boundary.

Correctness evidence: the producer independently constructs the ideal controlled-X matrix from logical column indices and a NumPy branch simulator for the emitted cleanup strategy. `result.json` records all 128 logical basis columns (five controls, target and reference) in each of eight outcome branches. Each forward and logical-inverse branch is numerically checked against the ideal channel divided by `sqrt(8)`, with maximum errors about `5.55e-17`. Removing phase correction gives fidelity about 0.5859375, so the negative control detects coherent damage. These are full finite matrix diagnostics for the fragment, evaluated in floating-point arithmetic. This review supplies no interval proof and did not parse/replay the exported QASM; the branch simulator and QASM are constructed from the same compute sequence.

Cost evidence: `result.json` records T count 49 to 28, equal ten-qubit footprint including the reference, three measurements and three sequential feedback rounds, with at most three conditional CZ and reset-X corrections. Measurement, feedback and routing latency are unresolved; no physical timing is measured. Its disposition forbids silently inserting this into unitary `Program.undo`.

Toolchain overlap: the prototype imports the same `Program`, `primitives.mcx` and `resources`; it uses the same local NumPy and Qiskit environment. Its direct ideal matrix/branch simulation is a differently structured correctness check, and emitted dynamic QASM demonstrates a fragment-level representation change. Full source integration and a separately independently implemented pricing backend remain absent.
